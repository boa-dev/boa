# Boa C bindings

`boa_ffi` exposes Boa through opaque C handles generated by Diplomat. The current
API supports context lifecycle and value handles with type inspection and
boolean/number/string/null/undefined construction and inspection, plus structured
error construction and inspection. It does not yet execute JavaScript. The API is
experimental and may change.

## Build and test

Use the Rust toolchain required by the workspace. From the repository root:

```sh
cargo build --locked -p boa_ffi
cargo test --locked -p boa_ffi
./ffi/boa_ffi/tests/c/run.sh
```

The library is `target/debug/libboa_ffi.dylib` on macOS or
`target/debug/libboa_ffi.so` on Linux with Cargo's default configuration. Include
`bindings/c/BoaContext.h`, `bindings/c/JsValue.h` and `bindings/c/JsError.h` as
needed in C programs and link against this library.

The C test runner requires a native macOS or Linux environment and a C11 compiler
(`cc`, or an executable specified by `CC`). By default it builds for the Rust
host explicitly in `target/<host>/debug/`, honors `CARGO_TARGET_DIR`, and runs
against that build's library; `--ci` reuses Cargo's `ci` profile build. Windows
support is not covered by this runner.

Rust tests cover initialization failure, context cleanup, value types, boolean,
numeric and string round trips (including unpaired UTF-16 surrogates), retained
error data and inspection without JavaScript execution.
Object retention is checked across garbage collection. The C tests exercise
context/value/error lifecycle, boolean/numeric/string edge cases and message
encoding through the generated headers and shared library. They check results
explicitly, so defining `NDEBUG` does not disable the tests. A dedicated CI job
runs header regeneration and the C tests across macOS and Linux.

## Regenerate headers

```sh
cargo run --locked -p diplomat-gen
```

Diplomat's version requirements live in the workspace `Cargo.toml`, and
`Cargo.lock` fixes the resolved versions, so no globally installed
`diplomat-tool` is needed. Regeneration replaces all of `bindings/c/`, including
removing obsolete headers. Do not edit those files by hand. Include regenerated
headers with changes to the Rust bridge.

## Context ownership

```c
#include "BoaContext.h"

int main(void) {
    BoaContext *context = boa_BoaContext_new();
    if (context == NULL) {
        return 1;
    }
    boa_BoaContext_destroy(context);
    return 0;
}
```

- `boa_BoaContext_new()` returns one owned handle, or `NULL` on an ordinary engine
  initialization error. It uses Boa's fallible context builder.
- Destroy each successful result exactly once with `boa_BoaContext_destroy()`.
  Its argument must be a live, non-null context pointer returned by this API.
  `boa_BoaContext_destroy(NULL)` is invalid. Do not use C's `free()` on a handle.
- Copying a pointer creates an alias, not another owned handle. After destruction,
  every alias is invalid.
- Use and destroy a context on the thread that created it. Calls on the same
  handle must not overlap. Multiple independent contexts can coexist on one thread.
- `NULL` does not represent recovery from arbitrary Rust panics or allocation
  failure. These failures may abort the process; this API does not catch panics.

## Value handles

Primitive constructors (`boa_JsValue_from_boolean`, `boa_JsValue_from_number`,
`boa_JsValue_from_string`, `boa_JsValue_from_null`, `boa_JsValue_from_undefined`)
require no context and return an owned `JsValue *` handle. All getters borrow a
live, non-null handle without coercing types, and return a tagged result whose
`is_ok` field must be checked before reading `ok` or `err`.

- **Type inspection (`boa_JsValue_get_type`):** Returns the ECMAScript language
  type (`JsValueType`). Unlike JS `typeof`, `null` and `undefined` are distinct
  and functions have type `Object`. Object identity is preserved.
- **Booleans (`from_boolean` / `as_boolean`):** Only boolean values return
  `is_ok == true`; truthy and falsy non-booleans return `is_ok == false`.
- **Numbers (`from_number` / `as_number`):** Only number values return
  `is_ok == true`, including `NaN`, infinities, and signed zeros (`NaN` payload
  bits are not guaranteed).
- **Strings (`from_string` / `as_string` / `as_string_lossy`):**
  - `from_string` copies a UTF-8 `DiplomatStringView` using its explicit byte
    length (including any `'\0'` bytes) and returns `NULL` on invalid UTF-8.
    Empty strings may pass `{.data = NULL, .len = 0}`.
  - `as_string` and `as_string_lossy` encode the string as UTF-8 into a
    `DiplomatWrite` buffer (from `diplomat_runtime.h`). On failure, nothing is
    written. `as_string` reports `JsStringError_NotAString` or
    `JsStringError_InvalidEncoding` (unpaired UTF-16 surrogates);
    `as_string_lossy` replaces unpaired surrogates with `U+FFFD` and only fails
    on non-strings.
  - Growable buffers (`diplomat_buffer_write_create`) are not NUL-terminated
    and JS strings may contain `'\0'`, so use `diplomat_buffer_write_len()`.
    Fixed stack buffers (`diplomat_simple_write`) append a trailing `'\0'` and
    set `write.grow_failed` on overflow.
- **Ownership & lifetime:** Keep handles on their creating thread. Primitive
  values remain valid after a `BoaContext` is destroyed. Destroy each owned
  handle once with `boa_JsValue_destroy()` (never `NULL` or `free()`).
  Allocation failures and unexpected Rust panics may abort the program.

```c
JsValue *num = boa_JsValue_from_number(7.0);
boa_JsValue_as_number_result n = boa_JsValue_as_number(num);
if (n.is_ok) {
    printf("%g\n", n.ok);
}
boa_JsValue_destroy(num);

const char text[] = "hello";
JsValue *str = boa_JsValue_from_string(
    (DiplomatStringView){.data = text, .len = sizeof(text) - 1});
if (str != NULL) {
    DiplomatWrite *write = diplomat_buffer_write_create(0);
    boa_JsValue_as_string_result res = boa_JsValue_as_string(str, write);
    if (res.is_ok) {
        fwrite(diplomat_buffer_write_get_bytes(write), 1,
               diplomat_buffer_write_len(write), stdout);
        fputc('\n', stdout);
    }
    diplomat_buffer_write_destroy(write);
    boa_JsValue_destroy(str);
}
```

## Errors

`JsError` retains Boa's original error and its stored representation:

- `Native` has a native category and UTF-8 message.
- `Opaque` contains an arbitrary thrown value, including JavaScript Error objects.
- `Engine` is an engine failure that JavaScript cannot catch.

`boa_JsError_get_representation()` and the getters inspect stored data without running
JavaScript. They do not read object properties or normalize opaque Error objects
into native errors. Engine details, cause/aggregate traversal and normalization
are not exposed yet; their underlying data remains in the error handle.

`boa_JsError_from_native()` copies the supplied UTF-8 message, using its explicit byte
length, including any embedded NUL. It requires no context and returns an owned
handle for each known category. Aggregate construction starts with no members.
The reserved `Other` category is for inspecting unrecognized native categories;
passing `Other` or malformed UTF-8 to the constructor returns `NULL`. Allocation
failures and unexpected panics may abort. Invalid enum discriminants and invalid
non-empty pointers violate the caller's contract.

```c
#include <stdio.h>
#include "JsError.h"

int main(void) {
    const char message[] = "invalid input";
    JsError *error = boa_JsError_from_native(JsNativeErrorKind_Type,
        (DiplomatStringView){.data = message, .len = sizeof(message) - 1});
    if (error == NULL) {
        return 1;
    }
    boa_JsError_as_native_result info = boa_JsError_as_native(error);
    if (!info.is_ok) {
        boa_JsError_destroy(error);
        return 1;
    }
    fwrite(info.ok.message.data, 1, info.ok.message.len, stdout);
    fputc('\n', stdout);
    boa_JsError_destroy(error);
    return 0;
}
```

`boa_JsError_as_native()` returns a tagged optional category/message pair. Check
`is_ok` before reading `ok`; an empty message is present, while an opaque or engine
error has no native details. The message bytes are borrowed from the error and
remain valid until that error is destroyed. Use the byte length, not `strlen()`
or `%s`. Do not free the message or retain its view after destroying the error.

`boa_JsError_from_opaque()` borrows a value and retains a clone; the caller keeps the
input handle and may destroy it independently. `boa_JsError_as_opaque()` returns a
new owned value handle for the stored payload, or `NULL` for native/engine errors.
Null and undefined payloads return present handles with their respective types.
Each returned payload must be destroyed with `boa_JsValue_destroy()`, independently
of the error. Object identity is preserved. Keep a context alive while using
resources that depend on it, including retained objects.

Use and destroy errors on their creating thread. Getters require live, non-null
handles. Destroy each owned error exactly once with `boa_JsError_destroy()`; pointer
aliases then become invalid. `boa_JsError_destroy(NULL)` and C's `free()` are invalid.
