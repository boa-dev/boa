# Boa C bindings

`boa_ffi` exposes Boa through opaque C handles generated by Diplomat. The current
API supports context lifecycle and value handles with type inspection and
number/null/undefined construction. It does not yet execute JavaScript. The API
is experimental and may change.

## Build and test

Use the Rust toolchain required by the workspace. From the repository root:

```sh
cargo build --locked -p boa_ffi
cargo test --locked -p boa_ffi
./ffi/boa_ffi/c/tests/run.sh
```

The library is `target/debug/libboa_ffi.dylib` on macOS or
`target/debug/libboa_ffi.so` on Linux with Cargo's default configuration. Include
`c/generated/BoaContext.h` and `c/generated/JsValue.h` as needed in C programs and
link against this library.

The C test runner requires a native macOS or Linux environment and a C11 compiler
(`cc`, or an executable specified by `CC`). It builds for the Rust host explicitly,
honors `CARGO_TARGET_DIR`, and runs against that build's library. Its library is in
`target/<host>/debug/` by default. Windows support is not covered by this runner.

Rust tests cover initialization failure, context cleanup, value types, numeric
round trips and object retention across garbage collection. The C tests exercise
context/value lifecycle and numeric edge cases through the generated headers
and shared library. They check results explicitly, so defining `NDEBUG` does not
disable the tests.

## Regenerate headers

```sh
cargo run --locked -p diplomat-gen
```

The workspace pins Diplomat and `diplomat-tool` to 0.15.0, with
`diplomat-runtime` 0.15.1. `Cargo.lock` also fixes their transitive dependencies;
no globally installed `diplomat-tool` is needed. Regeneration replaces all of
`c/generated/`, including removing obsolete headers. Do not edit those files by
hand. Include regenerated headers with changes to the Rust bridge.

## Context ownership

```c
#include "BoaContext.h"

int main(void) {
    BoaContext *context = BoaContext_new();
    if (context == NULL) {
        return 1;
    }
    BoaContext_destroy(context);
    return 0;
}
```

- `BoaContext_new()` returns one owned handle, or `NULL` on an ordinary engine
  initialization error. It uses Boa's fallible context builder.
- Destroy each successful result exactly once with `BoaContext_destroy()`.
  Its argument must be a live, non-null context pointer returned by this API.
  `BoaContext_destroy(NULL)` is invalid. Do not use C's `free()` on a handle.
- Copying a pointer creates an alias, not another owned handle. After destruction,
  every alias is invalid.
- Use and destroy a context on the thread that created it. Calls on the same
  handle must not overlap. Multiple independent contexts can coexist on one thread.
- `NULL` does not represent recovery from arbitrary Rust panics or allocation
  failure. These failures may abort the process; this API does not catch panics.

## Value handles

`JsValue_from_number(double)`, `JsValue_from_null()` and
`JsValue_from_undefined()` each return one owned, non-null value handle. They
require no context, and these primitive values remain usable after a context
is destroyed. Allocation failures and unexpected Rust panics may abort the process.

```c
JsValue *value = JsValue_from_number(7.0);
JsValue_as_number_result number = JsValue_as_number(value);
if (number.is_ok) {
    printf("%g\n", number.ok);
}
JsValue_destroy(value);
```

`JsValue_get_type()` borrows the handle and returns its `JsValueType`. It reports
the ECMAScript language type: null and undefined are distinct, and functions
have the object type. This differs from JavaScript's `typeof` operator.
The underlying handle retains the original Boa value, including object identity.

`JsValue_as_number()` borrows the handle and returns a tagged optional double.
Check `is_ok` before reading `ok`; only number values have a numeric payload.
Null and undefined produce an absent result without coercion. NaN is a present
number, as are infinities and signed zeros. NaN payload bits are not guaranteed.

All value calls, including destruction, must stay on the creating thread. Getters
require a live, non-null value handle and do not consume it. Destroy each owned
handle exactly once with `JsValue_destroy()`, and invalidate every pointer alias
afterward. `JsValue_destroy(NULL)` and C's `free()` are invalid for these handles.
