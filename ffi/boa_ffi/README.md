# Boa C bindings

`boa_ffi` exposes Boa through opaque C handles generated by Diplomat. The current
API supports context lifecycle, evaluating JavaScript source, value handles with
type inspection and number/null/undefined construction, and structured error
construction, inspection and conversion. The API is experimental and may change.

## Build and test

Use the Rust toolchain required by the workspace. From the repository root:

```sh
cargo build --locked -p boa_ffi
cargo test --locked -p boa_ffi
./ffi/boa_ffi/tests/c/run.sh
```

The library is `target/debug/libboa_ffi.dylib` on macOS or
`target/debug/libboa_ffi.so` on Linux with Cargo's default configuration. Include
`bindings/c/BoaContext.h`, `bindings/c/JsValue.h` and `bindings/c/JsError.h` as
needed in C programs and link against this library.

The default build enables the same engine features as Boa's WebAssembly
bindings: `annex-b`, `experimental`, `float16`, `intl_bundled`, `temporal` and
`xsum`. Scripts can therefore use `Intl`, `Temporal`, `Float16Array`,
`Math.sumPrecise` and the Annex B additions. `intl_bundled` embeds ICU data,
which makes a release library roughly three times larger. For a small build
without these features, add `--no-default-features`:

```sh
cargo build --locked -p boa_ffi --no-default-features
```

A single feature can be added back with, for example,
`--features boa_engine/temporal`. The C test runner builds the default
features and its tests expect them.

The C test runner requires a native macOS or Linux environment and a C11 compiler
(`cc`, or an executable specified by `CC`). By default it builds for the Rust
host explicitly in `target/<host>/debug/`, honors `CARGO_TARGET_DIR`, and runs
against that build's library; `--ci` reuses Cargo's `ci` profile build. Windows
support is not covered by this runner.

Rust tests cover initialization failure, context cleanup, value types, numeric
round trips, retained error data, inspection without JavaScript execution,
each kind of evaluation result and error conversion with every failure reason.
Object retention is checked across garbage collection. The C tests exercise
context/value/error lifecycle, numeric edge cases, message encoding, and
evaluation and error conversion (`tests/c/eval.c`) through the generated
headers and shared library. They check results explicitly, so
defining `NDEBUG` does not disable the tests. A dedicated CI job runs header
regeneration and the C tests across macOS and Linux.

## Regenerate headers

```sh
cargo run --locked -p diplomat-gen
```

Diplomat's version requirements live in the workspace `Cargo.toml`, and
`Cargo.lock` fixes the resolved versions, so no globally installed
`diplomat-tool` is needed. Regeneration replaces all of `bindings/c/`, including
removing obsolete headers. Do not edit those files by hand. Include regenerated
headers with changes to the Rust bridge.

## Context ownership

```c
#include "BoaContext.h"

int main(void) {
    BoaContext *context = boa_BoaContext_new();
    if (context == NULL) {
        return 1;
    }
    boa_BoaContext_destroy(context);
    return 0;
}
```

- `boa_BoaContext_new()` returns one owned handle, or `NULL` on an ordinary engine
  initialization error. It uses Boa's fallible context builder.
- Destroy each successful result exactly once with `boa_BoaContext_destroy()`.
  Its argument must be a live, non-null context pointer returned by this API.
  `boa_BoaContext_destroy(NULL)` is invalid. Do not use C's `free()` on a handle.
- Copying a pointer creates an alias, not another owned handle. After destruction,
  every alias is invalid.
- Use and destroy a context on the thread that created it. Calls on the same
  handle must not overlap. Contexts on the same thread share Boa's runtime,
  and each has its own globals.
- `NULL` does not represent recovery from arbitrary Rust panics or allocation
  failure. These failures may abort the process; this API does not catch panics.

## Evaluating JavaScript

`boa_BoaContext_eval()` runs source text as a script in a context. It returns
either the script's completion value or the error that stopped it.

```c
#include <stdio.h>
#include "BoaContext.h"
#include "JsError.h"
#include "JsValue.h"

int main(void) {
    BoaContext *context = boa_BoaContext_new();
    if (context == NULL) {
        return 1;
    }
    const char source[] = "6 * 7";
    boa_BoaContext_eval_result result = boa_BoaContext_eval(context,
        (DiplomatStringView){.data = source, .len = sizeof(source) - 1});
    if (result.is_ok) {
        boa_JsValue_as_number_result number = boa_JsValue_as_number(result.ok);
        if (number.is_ok) {
            printf("%g\n", number.ok);
        }
        boa_JsValue_destroy(result.ok);
    } else {
        /* A thrown value, such as the 7 in `throw 7`, is the error's payload.
           The payload is its own handle, so it can outlive the error. */
        JsValue *thrown = boa_JsError_as_opaque(result.err);
        boa_JsError_destroy(result.err);
        if (thrown != NULL) {
            boa_JsValue_as_number_result number = boa_JsValue_as_number(thrown);
            if (number.is_ok) {
                printf("threw %g\n", number.ok);
            }
            boa_JsValue_destroy(thrown);
        }
    }
    boa_BoaContext_destroy(context);
    return 0;
}
```

- The source is a pointer and a byte length, not a NUL-terminated string, so it
  may contain NUL. It must be UTF-8. The bytes are borrowed only for the call;
  the caller may change or free the buffer once it returns. Empty source may
  use a `NULL` pointer with length 0.
- Check `is_ok` before reading the result. Success carries `ok`, an owned value
  handle that is never `NULL`: empty source and source that only declares
  evaluate to undefined. Failure carries `err`, an owned error handle. Destroy
  whichever handle was returned, exactly once.
- The error is Boa's own, unchanged, so the functions under [Errors](#errors)
  apply. A value the script throws is `Opaque`, including Error objects:
  `throw 7` holds the number 7 and `throw new Error('boom')` holds the object.
  An error the engine raises that the script does not catch, such as a syntax
  error or an undefined name, is `Native`; if the script catches and rethrows
  it, it is `Opaque`. Exceeding an engine limit, such as the recursion limit,
  is `Engine`, and the context remains usable afterward.
- Source that is not valid UTF-8 fails with a `Native` type error, and nothing
  is evaluated.
- Calls on one context see globals defined by earlier calls, including changes
  made before a script threw.
- The context discards promise jobs as they are scheduled. A `then` callback
  never runs. Evaluating a rejected promise returns the promise as a value.
- When `eval` or `try_native` finishes running JavaScript, it releases the
  temporary references Boa keeps for `WeakRef`. An owned value handle still
  keeps its object alive until the caller destroys the handle.
- There is no time limit. A script that never finishes never returns.
- Returned handles do not borrow from the context. Each one may be inspected
  and destroyed before or after the context is destroyed.

## Value handles

`boa_JsValue_from_number(double)`, `boa_JsValue_from_null()` and
`boa_JsValue_from_undefined()` each return one owned, non-null value handle. They
require no context, and these primitive values remain usable after a context
is destroyed. Allocation failures and unexpected Rust panics may abort the process.

```c
JsValue *value = boa_JsValue_from_number(7.0);
boa_JsValue_as_number_result number = boa_JsValue_as_number(value);
if (number.is_ok) {
    printf("%g\n", number.ok);
}
boa_JsValue_destroy(value);
```

`boa_JsValue_get_type()` borrows the handle and returns its `JsValueType`. It reports
the ECMAScript language type: null and undefined are distinct, and functions
have the object type. This differs from JavaScript's `typeof` operator.
The underlying handle retains the original Boa value, including object identity.

`boa_JsValue_as_number()` borrows the handle and returns a tagged optional double.
Check `is_ok` before reading `ok`; only number values have a numeric payload.
Null and undefined produce an absent result without coercion. NaN is a present
number, as are infinities and signed zeros. NaN payload bits are not guaranteed.

All value calls, including destruction, must stay on the creating thread. Getters
require a live, non-null value handle and do not consume it. Destroy each owned
handle exactly once with `boa_JsValue_destroy()`, and invalidate every pointer alias
afterward. `boa_JsValue_destroy(NULL)` and C's `free()` are invalid for these handles.

## Errors

`JsError` retains Boa's original error and its stored representation:

- `Native` has a native category and UTF-8 message.
- `Opaque` contains an arbitrary thrown value, including JavaScript Error objects.
- `Engine` is an engine failure that JavaScript cannot catch.

`boa_JsError_get_representation()` and the getters inspect stored data without running
JavaScript. They do not read object properties or normalize opaque Error objects
into native errors; `boa_JsError_try_native()`, described below, does that as a
separate call. Engine details and cause/aggregate traversal are not exposed
yet; their underlying data remains in the error handle.

`boa_JsError_from_native()` copies the supplied UTF-8 message, using its explicit byte
length, including any embedded NUL. It requires no context and returns an owned
handle for each known category. Aggregate construction starts with no members.
The reserved `Other` category is for inspecting unrecognized native categories;
passing `Other` or malformed UTF-8 to the constructor returns `NULL`. Allocation
failures and unexpected panics may abort. Invalid enum discriminants and invalid
non-empty pointers violate the caller's contract.

```c
#include <stdio.h>
#include "JsError.h"

int main(void) {
    const char message[] = "invalid input";
    JsError *error = boa_JsError_from_native(JsNativeErrorKind_Type,
        (DiplomatStringView){.data = message, .len = sizeof(message) - 1});
    if (error == NULL) {
        return 1;
    }
    boa_JsError_as_native_result info = boa_JsError_as_native(error);
    if (!info.is_ok) {
        boa_JsError_destroy(error);
        return 1;
    }
    fwrite(info.ok.message.data, 1, info.ok.message.len, stdout);
    fputc('\n', stdout);
    boa_JsError_destroy(error);
    return 0;
}
```

`boa_JsError_as_native()` returns a tagged optional category/message pair. Check
`is_ok` before reading `ok`; an empty message is present, while an opaque or engine
error has no native details. The message bytes are borrowed from the error and
remain valid until that error is destroyed. Use the byte length, not `strlen()`
or `%s`. Do not free the message or retain its view after destroying the error.

`boa_JsError_from_opaque()` borrows a value and retains a clone; the caller keeps the
input handle and may destroy it independently. `boa_JsError_as_opaque()` returns a
new owned value handle for the stored payload, or `NULL` for native/engine errors.
Null and undefined payloads return present handles with their respective types.
Each returned payload must be destroyed with `boa_JsValue_destroy()`, independently
of the error. Object identity is preserved. A payload may outlive both the
error and the context it came from.

`boa_JsError_try_native()` converts an error into a new owned `Native` error, so
that C can read the category and message of a thrown Error object. A script's
`throw new Error('boom')` arrives as `Opaque`; converting it gives the category
`Error` and the message `boom`:

```c
#include <stdio.h>
#include "BoaContext.h"
#include "JsError.h"
#include "JsValue.h"

int main(void) {
    BoaContext *context = boa_BoaContext_new();
    if (context == NULL) {
        return 1;
    }
    const char source[] = "throw new Error('boom')";
    boa_BoaContext_eval_result result = boa_BoaContext_eval(context,
        (DiplomatStringView){.data = source, .len = sizeof(source) - 1});
    if (result.is_ok) {
        boa_JsValue_destroy(result.ok);
    } else {
        boa_JsError_try_native_result converted =
            boa_JsError_try_native(result.err, context);
        if (converted.is_ok) {
            boa_JsError_as_native_result info = boa_JsError_as_native(converted.ok);
            if (info.is_ok) {
                fwrite(info.ok.message.data, 1, info.ok.message.len, stdout);
                fputc('\n', stdout);
            }
            boa_JsError_destroy(converted.ok);
        }
        boa_JsError_destroy(result.err);
    }
    boa_BoaContext_destroy(context);
    return 0;
}
```

- Unlike the other error functions, it can run JavaScript. It reads properties
  of the Error object, such as `message` and `cause`, and a property may be a
  getter.
- Pass a live context on the error's creating thread. For a thrown Error
  object, use the object's original context to run its getters. A native error,
  including one created with `boa_JsError_from_native()`, can be copied with
  any live context on that thread.
- The original handle keeps its representation and payload. The converted
  error is a separate handle. Destroy both in either order.
- The category comes from the object's internal type, so an instance of a class
  that extends `Error` reports `Error`. Copying an already-native error
  preserves its captured JavaScript backtrace.
- Check `is_ok` before reading the result. On failure nothing is returned to
  destroy, and `err` is a `JsTryNativeError` reason:
  - `NotAnErrorObject`: the thrown value is not an Error object, as with
    `throw 7`.
  - `InvalidPropertyType`: `message` is not a string, or the `errors` of an
    aggregate error is not an array.
  - `InvalidMessageEncoding`: `message` contains an unpaired surrogate.
  - `InvalidConstructor`: `constructor` is missing or is not a constructor.
  - `InaccessibleProperty`: reading a property threw.
  - `InvalidErrorsIndex`: reading a member of an aggregate error's `errors`
    threw.
  - `InaccessibleRealm`: the realm of the constructor could not be found.
  - `EngineError`: the error is an `Engine` error, which has no native form.
- An exception thrown while reading a property is discarded; only the reason
  is reported.

Use and destroy errors on their creating thread. Getters require live, non-null
handles. Destroy each owned error exactly once with `boa_JsError_destroy()`; pointer
aliases then become invalid. `boa_JsError_destroy(NULL)` and C's `free()` are invalid.
